# Narragram 仕様書
対象：コーディングエージェントへの実装指示  
仕様バージョン：0.1（初期実装用）  
ステータス：設計仮説を含む。心理尺度としての妥当性は未検証。

## 1. 目的

異世界に転生した主人公が、ダンジョン探索や仲間との出来事で選択を重ねることで、ユーザーの「冒険スタイル」と性格傾向を提示するWebサイトを作る。

体験としての面白さと、心理学的な性格分析を分離する。冒険者タイプはエンターテインメント上の分類であり、心理学的に確立されたタイプであると表現しない。Big Fiveに基づく因子スコアも、妥当性を検証するまでは「探索的な傾向」として扱う。

## 2. MVPの範囲

実装対象：
- トップページ
- 診断イントロ／異世界転生導入
- 15問を基本とする選択式診断
- 結果ページ
- 詳細な性格傾向の説明
- 結果共有（共有URLまたは画像。回答の生データをURLに含めない）
- プライバシー・サイト説明ページ
- 設問と結果タイプをJSON等のデータとして管理
- 基本的な利用状況計測のためのイベント設計

MVPでは実装しない：
- 会員登録、ログイン
- ランキング、他ユーザー比較
- 診断結果を使った広告ターゲティング
- 検証前の偏差値・百分率・「科学的に正確」といった表示
- 管理画面。まずはJSONファイルとコード管理で運用する

## 3. 想定技術構成

- Next.js（App Router）+ TypeScript
- スマートフォン優先のレスポンシブUI
- 設問データ・結果タイプ・採点ルールを表示コンポーネントから分離
- 回答途中の一時保存は sessionStorage を基本とし、再読み込み時に復元
- 結果共有は、共有対象を明示的に選別する。個々の回答やセンシティブな推定情報をURLへ直接埋め込まない
- 計測を導入する場合は、開始・完了・設問離脱・共有など最小限のイベントとする
- 外部分析サービスの利用、回答保存、Cookie等についてはプライバシーページに記載する

既存リポジトリの規約・利用ライブラリ・デプロイ方式を最初に確認し、不要な技術変更は避けること。

## 4. 画面構成

### 4.1 トップページ `/`
- メインコピー（仮）：「あなたが転生したら、どんな冒険者になる？」
- 補助コピー：「選択から読み解く、あなたの異世界冒険スタイル。」
- メインビジュアル：神秘的なダンジョン入口、魔法陣、冒険者のシルエット
- CTA：「冒険を始める」
- 所要時間の目安：「全15問・約3分」（実測後に修正）
- 「登録不要」「正解なし」を表示
- 画面の最初の表示範囲で世界観と開始ボタンが伝わる構成

### 4.2 イントロ
- 短い異世界転生の導入文
- 診断に正解・不正解はないことを説明
- 必要なら回答データの扱いを短く説明
- CTAから第1問へ進む

### 4.3 診断ページ `/quiz`
- 1画面につき1問
- 進捗表示（例：04 / 15、プログレスバー）
- 場面タイトル、短い状況説明、必要に応じて挿絵
- 選択肢は基本2択。タップしやすいカードUI
- 選択後は明確な選択状態を表示し、「次へ」で進む
- 前の設問に戻って変更できる
- 戻った場合も回答を保持
- 再読み込みで可能な範囲の進行状態を復元
- キーボード操作とスクリーンリーダーに配慮
- 選択肢に「正しい／間違い」や善悪の評価を付けない
- 進行不能、データ不足、未知の設問IDに対するフォールバックを用意

### 4.4 結果ページ `/result`
表示順：
1. 冒険者タイプ名・イラスト・キャッチコピー
2. 「あなたの冒険スタイル」概要
3. 回答傾向から読み取れる行動の特徴
4. Big Fiveの5因子の説明（検証段階に応じて表示）
5. 強みと、状況によって注意したい傾向
6. 診断をやり直す／結果を共有する
7. 診断の性質と限界に関する注記

検証前は因子を数値で断定せず、必要に応じて「参考」「探索的な傾向」と表記する。データの裏付けがない説明を回答者の事実として断言しない。

### 4.5 サイト説明・プライバシー
- 何を目的とした診断か
- Big Fiveを参考にしているが、現段階では設問と採点が未検証であること
- 医療・臨床診断ではないこと
- 収集するデータ、利用目的、保存期間、第三者サービス、削除方針
- 問い合わせ先（運営情報が決まり次第記載）

## 5. デザイン方針

方向性：インディーRPGの公式サイトとファンタジー小説の装丁を組み合わせた、上質なダークファンタジー。

- 背景：深い紺、黒、暗い紫
- アクセント：魔法を連想する青緑、古びた金色
- 見出し：ファンタジー感のあるセリフ体を候補にする
- 本文：読みやすい日本語サンセリフ体
- UI：ステータスパネル、古地図、魔法陣、装飾罫線は控えめに使用
- ボタン：十分なコントラストとタップ領域を確保
- スマートフォン優先。本文と選択肢の可読性を装飾より優先
- アニメーションは短く控えめにし、OSの動きを減らす設定にも配慮
- 画像は世界観を補助するために使い、質問文や選択肢を画像内に埋め込まない
- 特定の既存ゲーム・アニメ作品のロゴ、キャラクター、固有意匠を模倣しない

## 6. 性格モデルと分類

### 6.1 参考モデル：Big Five
5因子を参考に、冒険中の選択に現れる傾向を整理する。

- 開放性（Openness）：知的好奇心、審美的感受性、創造的想像など
- 誠実性（Conscientiousness）：計画性、生産性、責任感など
- 外向性（Extraversion）：社交性、主張性、活力など
- 協調性（Agreeableness）：思いやり、敬意、信頼など
- 否定的情動性（Negative Emotionality）：不安、抑うつ傾向、情動の揺れなど

この5因子は連続的な特性であり、5種類の固定タイプに人を分類するものではない。

### 6.2 冒険者タイプ（仮）
- 探究者：未知の仕組みや謎を解き明かす
- 戦略家：情報を整理し、先を読んで行動する
- 守護者：仲間の安全やチームの安定を重視する
- 開拓者：自ら行動を起こし、新しい道を切り拓く
- 観察者：状況を見極め、細かな変化を捉える

上記はエンターテインメント上の仮分類で、心理学的に検証された分類ではない。名称・説明・割当ルールはデータとして管理し、後から変更可能にする。全ユーザーを無理に単一タイプへ割り当てるより、主タイプ＋補助的な傾向、または「複合タイプ」を許容できる構造にする。

### 6.3 設問と採点に関する必須ルール
- `item_bank.csv` の15問は「候補」であり、確定済みの尺度ではない
- CSVの「初期採点案」をそのまま本番の確定スコアとして実装しない
- 両方の選択肢が適応的・配慮的な項目を、善悪や性格の高低に単純変換しない
- 特に協調性・否定的情動性は、現行の選択肢だけでは直接測定できない候補がある。未検証の項目はBig Five得点に算入せず、物語上の行動傾向のみに利用する
- 「選択したからこの特性が高い」と断言せず、選択肢の意図と解釈の不確実性を考慮する
- 質問ID、因子仮説、採点ルール、結果タイプの割当ルールにバージョンを持たせる
- 診断結果には「エンターテインメント目的」「医療・臨床診断ではない」「研究・検証段階の傾向分析である」旨を表示する

## 7. 設問データの構造案

設問本文と採点ルールをUIコードに直書きしない。たとえば以下のようなJSON構造にする。

```json
{
  "version": "0.1",
  "items": [
    {
      "id": "O1",
      "scene": "遺跡探索",
      "prompt": "封印された遺跡で、未知の通路を発見した。",
      "question": "あなたならどうする？",
      "choices": [
        {
          "id": "A",
          "text": "壁の紋様や構造を調べ、通路の正体を推理する。"
        },
        {
          "id": "B",
          "text": "仲間と危険を分担し、慎重に通路を進んでみる。"
        }
      ],
      "traitHypotheses": ["openness"],
      "scoring": {
        "status": "hypothesis",
        "includeInBigFiveScore": false
      },
      "sourceItemId": "O1"
    }
  ]
}
```

これはスキーマ例であり、文面は既存CSVと照合して確定すること。`traitHypotheses` と `scoring` は別フィールドにして、行動解釈と心理得点を混同しない。採点が検証されるまでは `includeInBigFiveScore` を false とする。

結果タイプも別のJSONにし、`id`、`name`、`tagline`、`description`、`strengths`、`watchouts`、`image`、`assignmentRuleVersion` を持たせる。

## 8. 結果算出の初期方針

- 初期MVPでは、診断完了後に冒険者タイプを提示するためのルールベースの仮ロジックを実装してよい
- ただし、仮ロジックとBig Fiveの因子スコア計算をコード上で分離する
- Big Fiveスコアの検証が終わるまでは、未検証の設問を因子得点に合算しない
- ルールが未設定・同点・回答欠損の場合のフォールバックを実装する
- 診断ロジックは純粋関数として実装し、設問回答を入力に結果オブジェクトを返す
- テストケースを用意し、同じ回答と同じルールバージョンなら同じ結果になることを確認する
- ルール変更時に過去結果の解釈が変わり得るため、結果にルールバージョンを保存する

## 9. 計測と検証

計測候補：
- `quiz_started`
- `question_answered`（必要性を検討し、収集する場合は回答本文ではなく設問ID・選択IDに限定）
- `quiz_completed`
- `quiz_abandoned`（離脱設問IDは必要最小限）
- `result_shared`

- 個人を特定できる情報を診断回答と結びつけない
- 計測目的と保存期間を明示し、必要な同意を得る
- 回答データを収集しない構成を選ぶ場合、ブラウザ内のみで処理する
- 診断結果を本人の同意なしに広告ターゲティングなどへ転用しない

検証計画：
1. 5〜8人程度の認知インタビューで、質問文の理解、選択理由、想定外の解釈を確認
2. 小規模パイロットで各選択肢の選択率、離脱、所要時間を確認
3. 妥当性を高める場合、日本語版Big Five尺度との比較を計画する
4. 項目の修正前後を比較し、設問・採点のバージョンを記録する

上記の人数や進め方は実務上の初期案であり、統計的な妥当性を保証する基準ではない。

## 10. 参考資料

同梱資料を必ず確認すること：
- `research_brief.docx`：初期調査と性格モデルの整理
- `validation_review.docx`：既存質問候補のレビュー、検証計画
- `item_bank.csv`：15問の候補、因子仮説、リスク、暫定採点案

主要参考文献：
1. Yoshino et al. (2022), “A validation of the Japanese adaptation of the Big Five Inventory-2,” *Frontiers in Psychology*, 13, 924351. https://doi.org/10.3389/fpsyg.2022.924351
2. Namikawa et al. (2012), “Development of a short form of the Japanese Big-Five Scale, and a test of its reliability and validity,” *Japanese Journal of Psychology*, 83(2), 91–99. https://doi.org/10.4992/jjpsy.83.91

既存の尺度項目をそのまま掲載・複製・商用利用する場合は、利用条件・著作権・ライセンスを別途確認する。候補質問は独自に検証するための草案であり、既存尺度の代替として妥当性が確認されたものではない。

- [ ] キーボード操作、フォーカス表示、色コントラストに配慮する

## 12. コーディングエージェントへの作業指示

1. まずリポジトリを確認し、既存の構成・規約・デプロイ方式を把握する。
2. 同梱の研究資料とCSVを読んでから実装を始める。
3. 不明点を勝手に心理学的事実として補完しない。仮説・未検証の箇所はコメントとデータ上の状態で明示する。
4. まず画面遷移とデザインを完成させ、次にデータ駆動の質問表示、仮のタイプ判定、結果表示を実装する。
5. Big Fiveのスコアリングは、検証済みの根拠がない限り確定ロジックとして実装しない。
6. テスト、README、受け入れ条件のチェック結果を報告する。
7. 既存コードの全面的な書き換えや、仕様にないサービスへの依存追加を避ける。
